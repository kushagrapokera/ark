# M11 — Memory hardening + proof

Master plan: `plan.md` (root), milestone M11. Deliverables: idle
`malloc_trim`, bounded caps everywhere, a heap/RSS pass, and a large-repo
stress proof with the ≤100MB budget asserted.

## Environment reality (recorded up front)

- `heaptrack`, `valgrind`, `smem` and `/usr/bin/time` are **not installed** on
  this host. Installing system profilers is out of scope for the repo.
  Substitute evidence: period `malloc_trim`, `/proc/self/status` (VmRSS/VmHWM)
  + `/proc/self/smaps_rollup` (Pss), a built-in report log, and the existing
  process/proc caps.
- No Linux-kernel checkout exists on this machine (`/usr/src/linux-garuda` is
  an empty directory). The stress proof uses a synthetic kernel-scale repo
  (80k files + multi-hundred-thousand-line files) generated by
  `implementation/m11-memory-proof/stress.sh`; the measurement method is the
  same one the kernel clone would use. Cloning a 4GB kernel tree is not part of
  a local milestone run.

## New dependencies

NONE. `malloc_trim` uses the already-present `libc` crate (glibc/Linux);
RSS/PSS parsing is `/proc` text (Linux). On non-glibc/non-Linux the trim is a
no-op and the report is `None`.

## Hardening changes

1. **Idle `malloc_trim`** (`src/memory.rs` + `App::about_to_wait`):
   - trim when the app has been idle for `TRIM_IDLE` (3s) and at most once per
     `TRIM_MIN_INTERVAL` (30s);
   - schedule a wake for the idle deadline (without delaying flash/tree/term
     follow-ups — the earliest wake wins);
   - log `rss/hwm/pss` after trimming; `ARK_MEM_REPORT=1` promotes it to
     `info`, otherwise `debug`.
   - Pure `should_trim(now,last_activity,last_trim)` gates all of this and is
     unit-tested; `trim_heap()` itself is a no-panic no-op off glibc.
2. **Terminal tab cap** (`MAX_TERM_TABS = 8`): the tab vector cannot grow
   without bound; opening past the cap returns `TermError::TabLimit` (logged
   by the App). Shell, git-command and agent tabs all share the cap.
3. **Viewer-index budget** (`INDEX_BUDGET_BYTES = 32 MiB`, LRU):
   `BufferCache` evicts the least-recently-used viewer when the summed line
   indexes exceed the budget (and always keeps the just-opened one). This
   bounds heap even when several large files are viewed; mmaps remain
   viewport-touched and the file-count cap (8) still applies.
4. **Existing caps stay pinned** by a test: tree entries 50k/dir, viewer
   64MiB view, 2000 scrollback lines, 100k git status entries, 4000 diff
   marks, 256KiB config documents, 64KiB ark.toml, 8 terminals, 32MiB index.
5. **Explicit drops** already exist (terminal tab close, LRU eviction, config
   editor replacement/reload, commit/status snapshot replacement); M11 adds
   the trim/report and the two missing growth caps rather than a second cache
   path.

## Tasks (inline; TDD, tests first)

1. `memory.rs`: pure trim gating + `/proc` parsing/report + trim no-panic;
   caps test.
2. App idle trim wiring + activity timestamps + scheduled wake + report log;
   test `should_trim` separately.
3. Viewer index bytes + BufferCache aggregate budget and eviction tests;
   main uses the default budget.
4. Terminal tab cap + error; existing terminal/agent/git tabs share it.
5. Stress script + live run: 80k-file synthetic repo, 5 large files open,
   2 shell tabs, agent tab; measure VmRSS/VmHWM/PSS before/after idle trim;
   assert <100MB; record scale latency qualitatively.
6. Gates: cargo test, clippy, release build, ARK_SMOKE, RSS records.

## Acceptance criteria

- Idle `malloc_trim` runs after 3s of inactivity, no more than once per 30s,
  logs `trimmed/rss/hwm/pss`, and never blocks or crashes the UI.
- `MAX_TERM_TABS` rejects the 9th tab with a logged error; shell/git/agent
  tabs share the limit.
- Viewer LRU evicts when summed line indexes exceed 32MiB while retaining the
  open file; the test proves the budget, not just the file count.
- Caps test pins the documented limits.
- 80k-file synthetic stress: 5 open files + 2 terminals + agent tab stays
  below 100MB PSS/RSS; tree/git/scroll remain responsive (recorded).
- No new dependencies; `cargo test`/clippy/release/smoke green; RSS evidence
  recorded with the host's available `/proc` method.
